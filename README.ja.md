# Blender Parts Check

Blender で分割制作した部品を統合する前に、命名ペアとワールド境界を点検する
読み取り専用アドオンです。[English](README.md)

片側の部品が対象に見当たらない、読み込み時のサイズや配置がずれた、といった
確認を手助けします。評価済みメッシュをワールド座標に変換し、境界の中心と寸法を
比較します。自動修正や、完全なモデル検証は行いません。

## 検査すること

- 末尾が大文字の `.L` / `.R` の完全一致ペアだけを対象にします。
  `Arm.L.001`、`_L`、小文字、`LeftArm` などは推測しません。
- 相方が**指定した検査範囲内**にない場合は要確認の警告です。欠損の断定では
  ありません。Mirror が両側を生成している可能性があるため、その存在を表示します。
  無効な Mirror も存在表示の対象です。軸や設定は利用者が確認してください。
- X / Y / Z のワールド軸を法線とする平面と、そのオフセットを指定できます。
  中心を反転した位置の距離と、軸別の境界寸法差の最大値を別々に比較します。
- スケールの絶対値が 1 でない場合は注意、負のローカルスケール、ワールド変換の
  反転、親変換は情報として表示します。幾何不一致とは別扱いです。

Apply Transform、Mirror 作成、Rename、Delete、選択変更、blend の Save は
実行しません。評価用の一時メッシュだけを作成・解放します。設定と結果はメモリ内に
保持し blend に保存しません。JSON 出力は任意の別操作で、既存ファイルへの上書きを
拒否します。

## インストール・削除

**Windows / Blender 5.0.1 で試験済み**。マニフェストは 5.0 以降を要求します。
他のバージョンや OS は未試験です。

1. ソース ZIP ではなく **`blender_parts_check-0.1.0.zip`** を取得します。解凍は不要です。
2. Blender の「編集 → プリファレンス → エクステンションを入手」の右上メニューから
   「ディスクからインストール」を選びます。ZIP を指定し、必要なら有効化します。
3. 3D ビューポートの `N` サイドバーにある **Parts Check** を開きます。

削除はプリファレンスのアドオン／エクステンション一覧で無効化し、アンインストール
します。オブジェクトのプロパティ、ハンドラ、起動ファイル、シーンデータは追加しません。
自分で書き出した JSON は出力先に残るので、不要なら別途削除してください。

## 使い方

1. **オブジェクトモード**で Selected objects、Collection + children、Active view
   layer から範囲を指定します。コレクションの子も含みます。アクティブなビューレイヤー
   にないオブジェクトは未検査になります。
2. Plane normal と Plane offset を指定します。X / 0 はワールド YZ 平面です。
   原点、ローカル軸、3D カーソルを平面に使う機能はありません。
3. Absolute tolerance は **Blender 単位**、Relative tolerance は比率です。
   `0.001` は `0.1%` です。表示単位のメートル値などへ自動変換しません。
4. 意図的な非対称は Exclude exact names に名前を `;` 区切りで入力します。
   ペアの片側だけを除外してもペア比較を止めます。除外していない側のスケール等は
   検査します。名前に `;` を含む場合は Python の `Settings` を使ってください。
5. **Check Parts (read only)** を押します。結果は実行時点のスナップショットです。
   シーン、選択、範囲、設定、フレーム、モディファイアを変えたら再実行してください。
6. 必要なら最後の結果を新しい `.json` ファイルに出力できます。共有前に中身を
   確認してください。ローカル画面には名前が出ますが、JSON には出ません。

ペアのそれぞれのワールド境界ボックスの対角長のうち大きい方を `D` とし、許容距離を
`max(絶対許容差, 相対許容差 × D)` とします。中心距離と寸法差の最大値をこの値と
別々に比較します。共有用差分は `D` で割ります。対角長がゼロの点状ペアでは、
ゼロでない差分を 1 と表します。`.L` が座標の正側か負側かは決めつけません。

例えば寸法 `(2, 2, 2)` の立方体を `(2, 0, 0)` と `(-2, 0, 0)` に置くと境界比較を
通過します。後者を `(-2, 0.2, 0)` に移動すると `CENTER_MISMATCH`、正規化差分は
約 `0.05773503` です。[合成例](examples/README.md)も参照してください。

## 結果と制約

`WARNING` は差分や未検査項目の要確認、`INFO` は変換・モディファイア・命名に関する
情報です。不正な設定ではエラーで実行を中止し、古い結果を消します。検査できたペアが
ゼロの場合は「合格」と表示しません。

空メッシュ、メッシュ以外、コレクション／パーティクルのインスタンス生成元、Geometry
Nodes は**未検査**です。Geometry Nodes はメッシュ変換でインスタンスが落ちる場合が
あるため、実体化済みの形状だけを作るノードでも保守的に除外します。相方が存在しても
未検査なら「相方がない」とは報告しません。利用者が除外した対象は評価しません。

- **同じ境界でも形状が違えば見逃します。** 頂点、トポロジー、シルエット、衝突、
  交差、閉じたメッシュか、同一形状かを判定するツールではありません。
- 発光、マテリアル、テクスチャ、ライティング、UV、レンダリングの見た目は比較しません。
  左右の光り方の差を検出できるとは宣伝しません。
- 参照画像の認識や忠実な形状再現は行いません。
- 現在のフレームとビューポートの依存グラフを使います。レンダー専用の設定、別フレーム、
  シミュレーション、生成インスタンスは結果が違う可能性があります。大規模な評価は重く
  なります。
- 親・制約を含めた**現在の**ワールド形状を見ます。今後の親変更、Apply、制約変更で
  見た目がどう変わるかは予測しません。ローカル原点や変換が異なっていても、同じ
  ワールド境界なら幾何不一致にはしません。
- 常時監視はしません。境界比較に問題がないことは、統合全体の正しさの保証ではありません。

## 報告と個人情報

個人情報を抑えた JSON には実行内だけの `part_001`、問題コード、重要度、件数、
正規化した差分を出します。許可リスト方式で名前、コレクション名、blend パス、
ユーザー名、時刻、生の座標・寸法、平面オフセット、スケール値を出しません。
通信・テレメトリのコードはありません。**完全匿名を保証するものではありません。**
件数・比率・問題のパターンからプロジェクトの情報が分かる可能性があります。
ローカルパネルのスクリーンショットや Blender 自体のコンソールには個人情報が含まれ得ます。

## 開発・試験

```text
python -m unittest discover -s tests -v
blender --background --factory-startup --python-exit-code 1 --python tests/blender_integration.py
python tools/build_release.py
python tools/audit_public.py
```

統合試験は必ず独立した headless プロセスで実行してください。工場出荷状態のシーンを
合成メッシュに置換するので、作業中の Blender セッション内では実行しないでください。
個人モデルや画像は不要です。シーンの指紋を検査・出力の前後で比較します。
出力試験中のエラーメッセージは、既存 JSON への上書き拒否を確認する想定内のものです。

## 既存機能との関係

[Mirror](https://docs.blender.org/manual/en/latest/modeling/modifiers/generate/mirror.html)
は対称形状の生成、[3D Print Toolbox](https://extensions.blender.org/add-ons/print3d-toolbox/)
は印刷用メッシュの分析が主目的です。本ツールは複数部品の統合前点検という小さい範囲に
絞っています。類似ツールが存在しないという主張ではありません。
[設計ノート](docs/DESIGN.md)も参照してください。
