# Blender Parts Check

**部品を組み合わせる前に、配置やサイズのずれを点検。**

[English](README.md) | [日本語](README.ja.md)

分割制作したパーツを Blender へ統合するときの、小さな読み取り専用アドオンです。
対象を選び、対称面を指定して実行すると、命名された相方の不在やワールド境界の
違いを確認できます。

「読み込んだ部品の大きさや位置が違うかも」という場面の点検を助けます。
比較するのは境界ボックスで、形状や見た目の正しさを判定するものではありません。

[設定](#settings) · [制約](#limits) · [個人情報](#privacy) · [貢献](#contribute)

| 基本情報 | 内容 |
| --- | --- |
| 試験済み環境 | **Blender 5.0.1 / Windows** |
| バージョン条件 | マニフェストは **Blender 5.0 以降**を要求。他のバージョン・OS は未試験 |
| パネルの場所 | 3D ビューポート → `N` サイドバー → **Parts Check** |
| ペアの命名 | 末尾が大文字の完全一致：`Arm.L` ↔ `Arm.R` |
| 依存関係 | Blender のみ。追加 Python パッケージ・アカウントは不要 |
| 言語 | 説明書は英語・日本語。現在のパネル表示は英語 |

## こんな場面で使えます

- これから組み合わせる対象の中に、名前を付けた相方が見当たらない。
- 別に作って読み込んだ部品の位置や境界寸法がずれている。
- 境界の比較と一緒に、スケール・親・Mirror の状態も確認したい。

親変換や制約を含む、**現在のビューポートの評価済みメッシュをワールド座標で**
比較します。原点やローカル変換が違っても、同じワールド境界になることはあります。
警告は確認のきっかけであり、意図的な非対称を間違いと決めつけません。

<a id="install"></a>
## 3 ステップで導入

1. プロジェクトのリリース添付ファイルから **`blender_parts_check-0.1.0.zip`** を取得
   します。ソースから作る場合は `python tools/build_release.py` を実行すると `dist/` に
   生成されます。拡張 ZIP は解凍せずに使います。GitHub が自動生成する **Source code**
   ZIP と `blender-parts-check-source-0.1.0.zip` はソース用で、インストール用ではありません。
2. Blender の **編集 → プリファレンス → エクステンションを入手 → 右上メニュー →
   ディスクからインストール**を開き、拡張 ZIP を選びます。必要なら有効化します。
3. **3D ビューポート**に戻り、**`N`** を押して **Parts Check** を開きます。

完成済みの拡張 ZIP を使う場合、ターミナル操作は不要です。タブが出ない場合は、
アドオンが有効か、`N` を押すときにマウスが 3D ビューポート上にあるかを確認します。

**削除：** プリファレンスのアドオン／エクステンション一覧で無効化し、アンインストール
します。オブジェクトのプロパティ、起動ファイル、シーンデータは追加しません。
自分で出力した JSON は出力先に残るので、不要なら別途削除してください。

<a id="first-check"></a>
## 最初の検査

1. **オブジェクトモード**にし、`Arm.L` と `Arm.R` のような両側の部品を選びます。
   Shift を押しながらクリックすると複数を選択できます。
2. **Parts Check** を開き、**Scope** は **Selected objects**、**Plane normal** は
   **X**、**Plane offset** は **0** のままにします。ワールド YZ 平面を対称面にする設定です。
3. 下の小さい立方体の例では、2 種類の許容差を初期値 **0.001** のまま使います。
4. **Check Parts (read only)** を押し、**Last run snapshot** に出る結果を読みます。

`WARNING` は差分や未検査項目の要確認、`INFO` は変換・命名・モディファイアの情報です。
比較できたペアがゼロなら **No symmetry pairs inspected** と表示され、合格扱いには
なりません。範囲・モード・数値設定が不正な場合はエラーで中止し、古い結果を消します。

結果は自動更新されません。**オブジェクト、選択、設定、フレーム、モディファイアを
変えたら、また JSON を出力する前には再実行してください。**

<a id="example"></a>
## 立方体 2 個で試す

新しい試用シーンで、寸法 `(2, 2, 2)`、スケール `(1, 1, 1)` の標準立方体を 2 個用意
します。`F2` で名前を変更し、`N` サイドバーの **Item（アイテム）**タブで
Location（位置）を入力します。**Parts Check** に戻り、両方の立方体を選択します。

| 手順 | 合成モデルの設定 | X / オフセット 0 での結果 |
| --- | --- | --- |
| 1 | `Arm.L` は `(2, 0, 0)`、`Arm.R` は `(-2, 0, 0)` | 1 ペアを比較し、境界不一致なし |
| 2 | `Arm.R` の位置 Y だけを `0.2` に変更 | `WARNING: CENTER_MISMATCH` |
| 3 | Scope は Selected objects のまま、`Arm.L` だけを選択 | `WARNING: MISSING_PARTNER` |

手順 2 の **Difference / diagonal**（対角長で割った差分）は約 **`0.05773503`** です。
手順 3 は、相方がシーン内に存在していても、**選んだ検査範囲にはない**ことを表します。

再現可能な 5 個の立方体の例もあります。ソースのルートディレクトリから、`blender` に
コマンドでアクセスできる環境で、**新しいバックグラウンドプロセス**として実行します。

```text
blender --background --factory-startup --python-exit-code 1 --python examples/run_synthetic.py
```

そのプロセスの工場出荷状態のシーンを合成モデルに置換し、JSON を表示します。
blend や報告ファイルは保存しません。対話中の Blender や factory-startup 指定のない
実行は拒否します。[合成例の完全な報告](examples/sample-report.json)は、比較ペア 2 組、
メッシュ部品 5 個で、検出項目は次のとおりです。

```json
[
  {"code": "CENTER_MISMATCH", "severity": "WARNING", "objects": ["part_001", "part_002"], "normalized_difference": 0.05773503},
  {"code": "MISSING_PARTNER", "severity": "WARNING", "objects": ["part_003"]}
]
```

個人モデルの報告ではなく、新しく作った合成例です。[例の詳細](examples/README.md)に
各部品の設定を記載しています。

<a id="settings"></a>
## 検査範囲・許容差・除外を選ぶ

| パネルの項目 | 選び方 |
| --- | --- |
| **Scope** | Selected objects（選択中）、Collection + children（コレクションと子）、Active view layer（現在のビューレイヤー）。両側を範囲に含めます。現在のビューレイヤーにないコレクション内の物体は未検査です。 |
| **Plane normal / Plane offset** | X・Y・Z のワールド軸と座標。X / 0 は YZ 平面、Y / 3 はワールド Y = 3 の面です。カーソルやローカル軸は使いません。 |
| **Absolute tolerance** | Blender 単位での距離。初期値は `0.001`。表示単位のメートル値などへ自動換算しません。 |
| **Relative tolerance** | 大きい方の部品の境界ボックス対角長に対する比率。初期値 `0.001` は `0.1%` です。 |
| **Exclude exact names** | 意図的な非対称を `Badge.L;Badge.R` のように `;` 区切りの完全一致名で指定。片側だけの除外でも、そのペアの対称性比較を止めます。 |

ペアの**各ワールド境界ボックスの対角長のうち、大きい方**を `D` とし、許容距離は
`max(絶対許容差, 相対許容差 × D)` です。反転した中心どうしのユークリッド距離と、
軸別寸法差の最大値を、別々にこの値と比較します。報告用の差分は `D` で割ります。
対角長ゼロの点状ペアでは、ゼロでない差分を `1` と表します。

命名は末尾の大文字 **`.L` / `.R` だけ**です。`Arm.L.001`、`_L`、小文字、`LeftArm`
などは推測しません。`.L` が平面の正側か負側かも決めつけません。

除外した物体は評価しません。除外していない相方のスケールなどは個別に確認します。
名前に `;` が含まれる場合は、パネルの除外欄ではなく Python の `Settings` を使ってください。

## 検出項目の読み方

| コード | 意味 |
| --- | --- |
| `MISSING_PARTNER` | 範囲内に完全一致の相方がいません。追加する前に選択・除外・制作意図・Mirror 設定を確認します。 |
| `CENTER_MISMATCH` / `SIZE_MISMATCH` | 反転したワールド境界中心／ワールド境界寸法に、許容差を超える差があります。 |
| `UNAPPLIED_SCALE` | ローカルスケールの絶対値が 1 と異なります。統合前に確認します。 |
| `NEGATIVE_LOCAL_SCALE` / `WORLD_REFLECTION` / `PARENT_TRANSFORM` | 変換に関する情報です。幾何不一致のエラーではありません。 |
| `MIRROR_PRESENT` | Mirror が存在します。無効なものも表示します。両側を既に生成している可能性があるので、軸やビューポート設定を確認します。 |
| `UNPAIRED_NAME` | 対応する末尾ではないため、この物体の対称性を比較していません。 |
| `UNCHECKED_*` | 検査できなかったデータです。問題なしという意味ではありません。 |

空メッシュ、メッシュ以外、コレクション／パーティクルのインスタンス生成元、Geometry
Nodes、ビューレイヤーで参照できない物体、評価失敗・非有限座標は未検査です。
Geometry Nodes はメッシュ変換でインスタンスが落ちる場合があるため、実体化した
形状だけを作るノードでも保守的に除外します。相方が存在して未検査の場合は、
「相方がない」とは報告しません。

<a id="limits"></a>
## 読み取り専用の動作と、境界検査の限界

検査は **Apply Transform、Mirror の作成、名前変更、削除、選択変更、blend 保存を
実行しません。** 評価用の一時メッシュだけを作成・解放します。設定と結果の名前は
メモリ内に保持し、blend には保存しません。シーン更新ハンドラやタイマーも登録
しません。何を変更するかは利用者が判断します。

**境界比較で不一致がなくても、モデル全体が正しいとは限りません。**

- 中心・寸法が同じでも、形状は違う場合があります。頂点、トポロジー、シルエット、
  衝突、交差、閉じたメッシュか、同一形状かは検査しません。
- 発光、材質、テクスチャ、照明、UV、レンダリングの見た目は比較しません。
  左右の光り方の差は検査対象外です。
- 参照画像の認識や、忠実な再現度の評価は行いません。
- 現在のフレームとビューポートの依存グラフを使います。レンダー専用のモディファイア、
  シミュレーション、別のアニメーションフレーム、生成インスタンスは結果が違う
  可能性があります。大きいシーンでは評価に時間がかかります。
- 現在のワールド形状を測ります。今後の親変更、Apply Transform、制約変更による
  変化は予測しません。

Blender の [Mirror](https://docs.blender.org/manual/en/latest/modeling/modifiers/generate/mirror.html)
は対称形状の生成、[3D Print Toolbox](https://extensions.blender.org/add-ons/print3d-toolbox/)
は印刷用メッシュの分析が主目的です。本ツールは命名された部品の統合前点検に絞って
います。類似ツールが存在しないという主張ではありません。

<a id="privacy"></a>
## 任意の JSON 出力と個人情報

検査後の **Export last snapshot JSON** は、明示的に**新しい** `.json` ファイルを
出力する操作です。既存ファイルには上書きしません。ファイル選択をキャンセルすれば
何も書き出しません。共有前に中身を確認してください。

個人情報を抑えた報告には、実行内だけの `part_001` のような参照、コード、重要度、件数、
正規化した差分を出します。名前・コレクション名・blend パス・ユーザー名・時刻・
生の座標や寸法・平面オフセット・ローカルスケール値は出しません。
通信・テレメトリのコードはありません。

**完全匿名ではありません。** 件数・比率・問題パターンから、プロジェクトの情報が
分かる可能性があります。ローカルパネルには名前が表示され、スクリーンショットや
Blender のコンソールにも個人情報が含まれ得ます。

<a id="contribute"></a>
## 不具合報告・翻訳・開発への参加

小さく再現できる不具合報告、説明の改善、翻訳、範囲を絞ったコード変更を歓迎します。
不具合はリポジトリの **Issues**、修正提案は **Pull requests** を使い、次を記載してください。

- Blender のバージョンと OS。
- 検査範囲・平面・許容差・合成例の正確な `.L` / `.R` 名。
- 再現手順、期待した動作、実際の検出結果。

個人の blend ファイルではなく、最小限の合成例で再現してください。公開報告から
私的な名前・パス・スクリーンショット・認証情報を取り除いてください。日英の対応版・
使い方・制約を揃え、新しい翻訳には相互に移動できる言語リンクを付けてください。

コードを変更した場合はソースのルートで次を実行します。`blender` はコマンドで
アクセスできる必要があります。単体試験には Python 3.13.11 を使用しました。

```text
python -m unittest discover -s tests -v
blender --background --factory-startup --python-exit-code 1 --python tests/blender_integration.py
python tools/build_release.py
python tools/audit_public.py
```

統合試験は必ず独立した工場出荷状態のバックグラウンドプロセスで実行します。
そのシーンを合成物体に置換し、安全でない起動条件は拒否します。出力試験中の想定内の
エラーは、既存 JSON への上書き拒否の確認です。記録した基準は **Python 15 件・Blender
統合試験 20 件**です。ソース配布物の `docs/VALIDATION.md` と
[設計ノート](docs/DESIGN.md)も参照してください。ネイティブパネルやファイル選択の見た目、他の Blender／OS の
組み合わせは未検証です。
